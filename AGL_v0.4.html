0. Abstract and claim boundary

AGL v0.4 is a proposed, typed domain-specific language for designing agent workflows around Ambition, Goal, and Loop. It integrates Felix Rieseberg’s four dimensions of ambition with a distinct goal contract, an observation-trigger-response loop, and cross-cutting verification and governance.

New in v0.4: (i) one global symbol registry; (ii) a typed contract model; (iii) refinement constraints beyond field presence; (iv) a reference JSON Schema and static validator; (v) retrospective event-trace checks; (vi) an explicit conditional soundness claim; and (vii) a separation of scientific discovery from mere hypothesis generation.

Not claimed: AGL is not an Anthropic feature, its schemas are not native slash-command arguments, and the reference validator does not prove runtime correctness, novelty of discoveries, or independent evaluator trustworthiness.

3. Type system and design-by-contract

The language has first-class types Problem, Context, Proposal, Contract, GoalSpec, LoopSpec, Evidence, Verdict, and Trace. The type signatures below define composition rather than merely arranging slash commands.

A : Problem × Context → NonEmpty(Proposal)

Given original task x and context ξ, Ambition produces a nonempty collection Π of candidate proposals π. It may suggest methods and measures, but cannot grant authority.

Select : NonEmpty(Proposal) × Γ → Result(κ, Rejection)

Select applies governance Γ. Only an approved and frozen contract κ may enter execution. Rejection or deferral does not fabricate a contract.

G : κ × State → GoalOutcome × Trace

Goal execution receives the immutable contract, attempts permitted actions, records witnesses, and returns a status plus an auditable execution trace.

L : LoopSpec × PersistentState → Stream(Iteration)

Loop recurrence yields a sequence of observations and permitted actions. Its scheduler can be fixed, adaptive or externally event-driven at the AGL abstraction layer; native Claude /loop implements only part of this design.

Refinement typing

Passing a structural schema is necessary but not sufficient. A contract is admissible only if it is approved, immutable for the duration of the goal, within governance resources, and paired with a verifiable terminal condition. A loop is admissible only if safety enforcement is configured for replay, storage, authority, budgets and concurrency.

WellFormed(spec) = SchemaValid(spec) ∧ ReferencesResolve(spec) ∧ RefinementsHold(spec)

WellFormed is a design-time predicate. It does not imply that the implementation or the environment is correct.

4. Typed grammar of Ambition — A

Grammar: Ambition comprises four independently adjustable dimensions. They are not automatically sequential, and all four can be represented even when the proposal emphasizes only a subset.

A — abstract operator grammar
AMBITION {
  S: SPEED {
    BASELINE; Cost_S; QUALITY_FLOOR;
    SAME_OUTCOME_CONSTRAINT; MEASUREMENT
  }
  H: ALTITUDE {
    TASK; IMMEDIATE_GOAL; ULTIMATE_GOAL;
    OBSERVABLE_OUTCOME; DELEGATION_BOUNDARY;
    CAPABILITY_REQUIREMENTS
  }
  D: DEPTH {
    EXPERT_STANDARD; INSTRUMENTS;
    STRETCH { TARGET; FEASIBILITY_TEST }
    CHALLENGE { ASSUMPTIONS; FALSIFICATION }
    DISCOVERY {
      KNOWLEDGE_BASELINE; EXPLORATION_POLICY;
      SURPRISE_DETECTOR; HYPOTHESIS_GENERATOR;
      DISCRIMINATING_EXPERIMENT; EVIDENCE_EVALUATOR;
      KNOWLEDGE_REVISION_RULE; NOVELTY_CHECK;
      REPLICATION_POLICY; STOPPING_RULE
    }
    OUTSIDE_JUDGE
  }
  R: RANGE {
    ARTIFACT_NOUN
    VERBIFY { ACTOR; ACTION_VERB; INTENDED_EFFECT;
              OPERATING_CONTEXT; SUCCESS_OBSERVATION;
              OUTPUT: FUNCTIONAL_OBJECTIVE }
    DISCIPLINE_DISCOVERY(INPUT: VERBIFY.OUTPUT)
    TRANSFER { METHOD; APPLICABILITY_TEST }
    CREW { FUNCTIONS; DELIVERABLES }
    INTEGRATION { CONFLICT_RESOLUTION; OUTCOME_TEST }
  }
  PROPOSAL_POLICY { SELECTION_RULE; UNCERTAINTY_REPRESENTATION }
}

4.1 Speed — S

Speed must optimize the cost of producing the same accepted outcome. A lower cost without preservation of outcome is not an improvement in Speed.

minπ ∈ Πκ CostS(π)   subject to   Q(π) ≥ qmin

Here Πκ denotes those candidate proposals satisfying contract κ. Q measures quality and q_min is the minimum accepted quality. Cost_S may scalarize wall time, monetary expense and human attention using declared nonnegative weights and units; its exact form is chosen by the contract. The quality floor must not stand in for the requirement to preserve the objective.

4.2 Altitude — H

Requires task → immediate goal → ultimate goal → observable outcome. It also specifies which decisions the agent may own and what capabilities are missing. A proposed higher-altitude objective must not bypass authorization.

4.3 Depth — D

Retains Felix’s professional instruments, stretch targets, adversarial challenge, knowledge discovery and outside judge. Unlike v0.2, discovery is an epistemic state transition, not just an output label.

et → zt → ηt → discriminating test → Kt+1

Evidence e_t is compared with the validated knowledge state K_t. A discrepancy score z_t exceeding a prespecified threshold δ prompts the generation of a candidate hypothesis η_t. Independent tests, replication and scrutiny may then justify revising the knowledge state. An anomaly alone does not establish discovery.

Epistemic discipline: Hypothesis generation ≠ empirical support ≠ scientific novelty. The third requires an appropriate prior-art search and evaluation beyond the training or observation set. Repeated exploratory testing requires controls for selection bias and false discoveries.

4.4 Range — R

The critical dependency is an explicit noun-to-verb transformation ρ_NV. Discipline discovery consumes the resulting functional objective φ; it must not independently begin from the original noun description.

ρNV(artifact noun, ξ) → φ → discipline discovery → method transfer

The VERBIFY sub-contract must identify an actor, an action verb, the intended effect, operating context and observable success. Transfer must identify actual professional methods, applicability assumptions and integration tests. Merely prompting specialist personas fails the Range refinement.

4.5 Proposal selection

Ambition returns multiple possible π values, with expected benefits, uncertain feasibility, costs, risks and proposed acceptance tests. Governance Γ determines whether a proposal may become κ. The selection rule may be multicriteria or Pareto-based: no obligation exists to maximize ambition in isolation.

5. Typed grammar of Goal — G

G — abstract operator grammar
GOAL {
  CONTRACT_REF; EXECUTOR_ID; OBJECTIVE
  PRECONDITIONS
  COMPLETION { PREDICATE; CHECKS }
  WITNESS { EVIDENCE_SCHEMA; PROVENANCE_REQUIREMENTS }
  EVALUATOR_REF -> VERIFIER
  INVARIANTS { STATE; TRANSITIONS; ACCEPTANCE }
  EXECUTION_POLICY { PERMITTED_METHODS; RETRY_POLICY }
  BUDGET { MAX_TURNS; MAX_ELAPSED_SECONDS; MAX_MONEY }
  TERMINATION {
    VERIFIED_SUCCESS | BLOCKED |
    BUDGET_EXHAUSTED | CANCELLED
  }
  OUTPUT { ARTIFACTS; REPORT_PATH }
}

5.1 Distinguish four things

ElementMeaningMay it be inferred from an assertion?
ObjectiveDesired state of the worldNo
Completion predicate PκCondition that must hold for contract κNo
Witness WκRequired evidence and provenance schemaNo
Verifier VκProcedure that checks evidence against criteria and issues a verdictNo — it must actually execute
Vκ(et, Pκ) ∈ {PASS, FAIL, INCONCLUSIVE}

A verifier may return PASS only if the specified evidence suffices under its declared assumptions. The model evaluator built into /goal is a continuation mechanism that judges the transcript; it is not automatically an external verifier.

5.2 State vs. transition obligations

The symbol Iκ uniquely denotes the always-on state invariant for κ. The symbol ΘΓ uniquely denotes the authorization predicate for governance Γ. The index t denotes the execution step; s_t is its observed state and a_t the action at that step.

∀t ≥ 0: Iκ(st) = true
∀t ≥ 0: ΘΓ(st, at, st+1) = true

The first applies to always-on properties; the second to authorized transitions. Acceptance-only properties belong to the final verifier rather than being mislabeled universal invariants.

5.3 Terminal states

The language distinguishes VERIFIED_SUCCESS, BLOCKED, BUDGET_EXHAUSTED and CANCELLED. A complete orchestrator may also record FAILED and INCONCLUSIVE as evaluation outcomes; the reference schema exposes the four operational terminal statuses. Termination itself is not proof of success.

6. Typed grammar of Loop — L

L — abstract operator grammar
LOOP {
  CONTRACT_REF
  TIMING { MODE: FIXED | ADAPTIVE | EVENT; INTERVAL? }
  OBSERVATION { SOURCES; FRESHNESS_RULE }
  CHANGE_DETECTION { EVENT_KEY; CHECKPOINT; COMPARISON }
  TRIGGER { PREDICATE; SIGNIFICANCE_RULE }
  RESPONSE { AUTHORIZED_ACTIONS; NO_CHANGE: NO_OP;
             ON_VIOLATION: HALT | ESCALATE }
  PERSISTENT_STATE { STORE; CHECKPOINT_POLICY; DURABILITY }
  SAFETY {
    IDEMPOTENCY { EVENT_KEY; EFFECT_KEY; REPLAY_POLICY }
    CONTINUITY { ATOMIC_CHECKPOINT; CRASH_RECOVERY }
    BOUNDEDNESS { PER_RUN_CAP; CUMULATIVE_CAP;
                  MAX_RETRIES; EXPIRY }
    SCOPE { APPROVED_CONTRACT; APPROVAL_MECHANISM }
    CONCURRENCY { PROTECTED_RESOURCES;
                  COORDINATION; CONFLICT_POLICY }
  }
  ENFORCEMENT { STATIC_CHECKS; RUNTIME_GUARDS; VIOLATION }
  TERMINATION { STOP_PREDICATE; EXPIRY_BEHAVIOR }
  OUTPUT { EVIDENCE_LOG; STATE_LOG }
}

6.1 Observe → detect change → trigger → respond → checkpoint

The loop’s temporal policy τ says when to inspect. Its observation function Ω returns evidence. Its change detector Δ separates new evidence from repeats. Its trigger χ determines whether a response is justified, and F defines permitted responses. Persistent state σ_t records checkpoints and handled effects.

et = Ω(σt) ;   Δ(et,σt) → χ → F or NO_OP

Doing nothing when no material evidence changed is a successful loop iteration, not a failure.

6.2 Five safety refinements

ObligationSpecification fieldExternal enforcement requirement
IdempotencyEvent and effect identity; replay policyAtomic effect ledger or provider idempotency support
State continuityCheckpoint, atomicity, crash recoveryDurable transactional store and reconciliation
BoundednessPer-run and cumulative limits; expiryMetering enforced before action and across sessions
Scope authorityContract reference, permission and approvalLeast privilege, independent action admission
ConcurrencyProtected resources, lease or lock, conflict policyShared coordination and conflict resolution
Do not confuse declared mechanisms with guarantees. Logging authorization_checked: true is not proof authorization really happened. A trace auditor is not an atomic storage system. Exactly-once external effects usually require coordination with the recipient service, not just checking a local event ID.

6.3 Scheduler portability

The abstract Loop type supports fixed, adaptive, and event timing. Claude Code’s documented /loop is in-session scheduling with fixed or dynamic recurrence, while persistent cloud routines and other event infrastructure address longer-lived behavior. The language should not promise a scheduler capability it has not bound to a compatible runtime.

7. Typed composition of the four patterns

PatternCanonical typed pipelineValidation emphasis
P1 SprintA → Select → G → VContract frozen before execution; terminal witness accepted
P2 RadarA → Select(charter) → L[Δ ⇒ A]Opportunity discoveries do not authorize their implementation
P3 WatchdogG → V → L[χ ⇒ F]Subsequent actions remain inside the committed repair scope
P4 Factory(A → Select → G → V → L → J)*Each strategic revision requires a fresh contract and independent review

In P2, Select(charter) authorizes a bounded discovery workflow; it does not authorize every proposal that workflow subsequently generates. The current reference schema consequently requires a frozen contract for monitoring patterns as well as for goal execution.

In P4, J is review, while R remains Range. The Kleene star denotes possible iteration and is constrained by expiry, approval and resource caps; it is not a license for perpetual unattended action.

8. Static checking and reference implementation

The downloadable package includes schema.json (Draft 2020-12), validate_agl.py, an abstract valid specimen, a unique-symbol registry, and 11 tests. These constitute a working reference preflight, not a complete AGL compiler.

01
Schema type-checking

Recognizes structural fields, types, enumeration values, conditional presence and numeric bounds.

02
Cross-field checking

Resolves contracts and evaluators, checks frozen approvals, enforces declared scopes, sums reserved budgets, validates timing and guards.

03
Trace auditing

Checks an emitted log for duplicate effect IDs, missing recorded authorization, stale checkpoints, and observed budget overruns.

04
Runtime enforcement

Requires real trusted storage, provider permissions, effect-aware idempotency, resource metering, and independent evaluation. Not implemented by this reference.

Reference check coverage

  • Expressed and checked: structure, names and typed fields; conditional pattern requirements; contract reference equality; policy scope subset; frozen approval; distinct executor and evaluator IDs; declared guards; static budget cap arithmetic.
  • Trace-audited if logged: duplicate effect IDs; authorization claim presence; lease reference presence; checkpoint ordering; observed per-run and cumulative costs.
  • Not verified: honest logs; atomic commits; correctly implemented leases; independently trusted evaluation; real-world success; rigorous scientific novelty.

A future full compiler could emit Claude prompts and trusted wrappers from a validated AGL specification. That transformation is not implemented here.

9. Conditional soundness: what can be established?

Definition: A validator is structurally sound for a stated rule when acceptance implies that the rule has been checked correctly. That is different from proving the controlled agent safe.

A conditional safety proposition

Assume (1) every consequential action passes an independent, correctly implemented authorization guard; (2) all side effects and checkpoints are atomically or safely reconciled; (3) distributed concurrency is correctly controlled; (4) resource meters are trustworthy; and (5) external verification evidence is authentic and the verifier is sound for its specified acceptance predicate.

Then an execution that passes all these runtime guards and ends with an accepted verifier result can be considered compliant with the declared authorization, accounting and acceptance conditions.

This is a conditional proposition, not an established theorem about Claude Code or the provided Python validator. Removing any assumption weakens the conclusion. It does not imply that the chosen objective is beneficial, that scientific claims are true outside the test domain, or that model behavior is generally aligned.

Independent evaluation as a trust boundary

The native /goal evaluator cannot substitute for Vκ unless its verification needs are wholly satisfied by trusted transcript-visible evidence and the remaining limitations are accepted. For consequential changes, prefer tool-executed tests with provenance retained outside the worker's unrestricted control.

10. Epistemic progress is a separate acceptance dimension

Felix's Depth dimension ultimately aims beyond polished execution: a model should be able to learn something that was not known to the current investigator. v0.4 therefore treats discovery as a typed sequence of epistemic transitions rather than a prompt adjective.

StageNecessary demonstrationWhat it does not prove
SurpriseObservation violates a specified expectationThat a new hypothesis is correct
HypothesisCandidate explanation with testable predictionsThat the hypothesis is supported
Empirical supportDiscriminating test on appropriate held-out evidenceScientific novelty or causal identification
ReplicationReproduction under independent conditionsUniversal validity
NoveltyDocumented comparison to prior literature and baselinesImportance or generality beyond evidence

A useful epistemic evaluator should be able to return INCONCLUSIVE without treating it as execution failure. Under severe distribution shift, even reproducible findings can fail to generalize. AGL should reward calibrated uncertainty and well-documented null results instead of maximizing discoveries by quantity.

11. Threat model and open proof obligations

  • Prompt injection: Retrieved logs, web pages and repository content may contain instructions that must remain data, not authority.
  • Approval spoofing: A text field naming an approver does not replace a cryptographically or operationally trusted approval mechanism.
  • Evidence contamination: Workers may alter test fixtures, evaluation criteria, baselines or data partitions.
  • Replay and side-effect races: Crashes between an external action and local checkpoint can cause duplicate effects without transactional reconciliation.
  • Metric gaming: The system may optimize a narrow score at the expense of the human's actual objective.
  • Strategic drift: Repeated ambition reviews may expand or replace the approved mission unless contract revisions are gated.
  • Epistemic false positives: Repeated search over many hypotheses can manufacture apparently striking discoveries.

AGL v0.4 specifies places where these risks must be checked; it does not provide a complete defense. Runtime enforcement and adversarial testing are separate implementation projects.

13. What's next — AGL v0.5

The next version should not add more named prompt patterns. It should close the most important implementation gaps:

  1. Trusted action admission: implement authorization, resource budgets and stateful effect keys as a real runtime guard before tool calls.
  2. Verified state machine: formalize action transitions, crash/retry semantics and distributed lease rules; model-check safety conditions.
  3. Evidence adapters: distinguish produced output from independent measurement, with protected benchmark versions and authentic provenance.
  4. Empirical evaluation: test whether AGL’s additional structure improves independently accepted work per human-hour, net of latency, dollar cost, and failure rates.
Research-level question: Under what conditions does strategic reframing have positive expected value, and can an agent learn when not to invoke Ambition? A metareasoning policy should compare expected decision improvement against the cost and risk of reconsideration, rather than maximizing the frequency of ambitious plans.
